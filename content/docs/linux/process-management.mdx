Commands for inspecting running processes, handling signals, managing persistent systemd services, and running tasks detached from interactive shell sessions.

---

## 1. Locate Running Processes

Locate processes by command name, pattern, or argument string:

```bash title="Query Process List"
# View all running processes with user, PID, CPU, memory, and command
ps aux | grep -i "node"

# Exclude the grep command itself from the output
ps aux | grep "[n]ode"
```

```bash title="Fast Process Filtering (pgrep)"
# Print PID and full command line matching a pattern
pgrep -fl "python"

# Filter processes owned by a specific user
pgrep -u www-data -l
```

```bash title="View Hierarchical Process Tree"
# Display parent-child hierarchy with PIDs
pstree -p -u
```

## 2. Terminate Hanging Processes

Always prefer graceful shutdown (`SIGTERM`) before resorting to uncatchable forced termination (`SIGKILL`):

```bash title="Process Termination by PID"
# Send SIGTERM (Signal 15) - Allows cleanup, saving state, closing sockets
kill 12345

# Send SIGKILL (Signal 9) - Immediate termination by the kernel (no cleanup)
kill -9 12345
```

```bash title="Batch Termination by Name or Pattern"
# Gracefully kill all processes matching a name
killall node

# Forcefully kill all processes matching a full command pattern
pkill -9 -f "webpack-dev-server"
```

```bash title="Signal Quick Reference"
# List all available signals
kill -l

# Key Signals:
# 1  (SIGHUP)  : Reload configuration without restarting
# 2  (SIGINT)  : Interactive interrupt (Ctrl+C)
# 9  (SIGKILL) : Forceful immediate kill (cannot be caught or ignored)
# 15 (SIGTERM) : Graceful termination request (Default)
```

## 3. Systemd Service Control

Manage daemons, web servers, and background workers registered as systemd units:

```bash title="Service Lifecycle Operations"
# Check detailed status, PID, active memory, and recent log snippet
sudo systemctl status nginx

# Start, stop, and restart a service
sudo systemctl start docker
sudo systemctl stop docker
sudo systemctl restart docker

# Reload service configuration without dropping active connections
sudo systemctl reload nginx
```

```bash title="Boot Enablement & Status Auditing"
# Enable service to start automatically on system boot
sudo systemctl enable nginx

# Enable and immediately start the service in one command
sudo systemctl enable --now nginx

# List all failed services currently in an error state
systemctl --failed --type=service
```

## 4. Real-time Service Logs (`journalctl`)

Query structured system logs generated by systemd units:

```bash title="Inspect Service Logs"
# Follow live logs for a specific service (like tail -f)
sudo journalctl -u nginx -f

# View the last 100 log lines without entering a pager
sudo journalctl -u docker -n 100 --no-pager

# View logs for a service since today or a specific time
sudo journalctl -u redis-server --since "1 hour ago"
```

```bash title="System Boot & Error Filtering"
# View errors from current boot session only
sudo journalctl -p err -b --no-pager

# View kernel logs
sudo journalctl -k -n 50
```

## 5. Background Jobs & Terminal Detachment

Run long-running scripts and builds that must continue executing after logging out of an SSH session:

```bash title="Detached Background Execution (nohup)"
# Redirect stdout and stderr to a log file and run in background
nohup ./long-running-build.sh > build.log 2>&1 &

# Verify active background jobs in the current shell session
jobs -l
```

```bash title="Bring to Foreground or Background"
# Resume background job %1 in foreground
fg %1

# Resume a suspended job (Ctrl+Z) in background
bg %1

# Disown a running process so it survives terminal closure
disown -h %1
```

```bash title="Persistent Shell Sessions (tmux)"
# Start a new persistent terminal session
tmux new -s deploy

# Detach from session: Press Ctrl+B, then release and press D

# Re-attach to existing session after reconnecting via SSH
tmux attach-t deploy

# List active sessions
tmux ls
```

## 6. Process Priority & Throttling (`nice` / `renice`)

Adjust CPU scheduling priority for resource-intensive compilation, video encoding, or backup jobs:

```bash title="Schedule with Low Priority"
# Launch command with lowest CPU scheduling priority (nice value 19)
nice -n 19 tar -czf backup.tar.gz /var/www

# Adjust priority of an already running process (PID 4321)
sudo renice -n 10 -p 4321
```
*(Nice values range from `-20` highest priority to `19` lowest priority. Default is `0`.)*
